Phase: 0°
Duty cycle: 50%

This example shows CircuitJS1.setExtClock() - a way to introduce a signal that JS can adjust on the fly WITHOUT defeating the digital fast path. The circuit (circuits/jsinterface-phase.txt) contains an ExtClockElm named "extclock": a JS-nameable digital clock rail (see ExtClockElm.ts). Unlike CircuitJS1.setExtVoltage() - which only works because JS calls it again every single frame to push in a fresh analog value, an approach the digital engine can't cheaply support for a "sleeping" chip that skips real ticks entirely - an ExtClockElm is a genuine periodic source built from the same phasedClockLogic()-based Cycle/outputEvents machinery every other digital clock rail uses (see clockChip.ts/RailElm.digitalSynthesis()). It free-runs entirely inside the simulator; the sliders below only call CircuitJS1.setExtClock("extclock", phaseRadians, dutyCycleFraction) once per drag, which re-primes that one rail's next edge in place (RailElm.retimePhase()) - no per-timestep JS callback needed to keep the signal alive between nudges. The PHASE raster below plots "extclock" the same change-list-driven way the D0 raster does, so dragging the slider visibly slides the edge within each line in real time.
